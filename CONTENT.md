# Як писати контент тренажера

Контент лежить у `src/content/`: уроки в `lessons/`, задачі практикуму в `practice/`.
Новий модуль чи рівень: новий файл, реєструвати ніде не треба. Порядок: за іменем
файлу з природним сортуванням (`m9-...` перед `m10-...`).

Головне правило: **очікуваний вивід і числа в перевірках не пишуться з голови.**
Пишеш еталонний розв'язок, запускаєш `npm run verify -- --only <id>`, і справжній
вивід Pyodide з'являється у звіті. Його й переносиш у `expected`/`output`, переконавшись,
що він правильний за змістом.

## Середовище, у якому виконується код учня

Pyodide 314.0.7 у браузері: Python 3.14, pandas 3.0.2, numpy 2.4.6, matplotlib 3.10.8
(бекенд Agg, графіки показуються картинками під кодом). Особливості, що впливають на вивід:

- pandas 3: рядкові колонки мають dtype `str`, а не `object`; copy-on-write увімкнено завжди,
  тож ланцюгове присвоєння `df[df.a > 1]["b"] = 0` нічого не змінює (це корисно показувати),
  `inplace=True` на колонці теж не діє; правильно `df.loc[mask, "b"] = 0` або `df["b"] = ...`.
- numpy у WebAssembly (32 біти): `np.array([1, 2]).dtype` дає `int32`, і `astype(int)`
  теж дає `int32`. pandas для цілих колонок, створених з даних Python, дає `int64`.
  Якщо dtype видно у виводі, задавай його явно: `astype("int64")`.
- numpy 2: скаляри всередині списків друкуються з типом: `[np.int32(5), np.float64(2.5)]`.
  Якщо треба гарний вивід, перетворюй: `int(x)`, `float(x)`, `.tolist()`.
- `pd.to_datetime(s, format="mixed", dayfirst=True)` переставляє день і місяць і в
  ISO-датах: `"2024-03-05"` стає 3 травня. Якщо серед даних є ISO, розбирай кожен формат
  окремо з `errors="coerce"` і зводь через `fillna`.
- `sorted()` і `sort_values()` порівнюють коди символів, тому є, і, ї, ґ стоять після я:
  `['агрус', 'гора', 'яблуко', 'єнот', 'інжир', 'їжак', 'ґанок']`. В умові не називай
  такий порядок алфавітним.
- `pd.set_option("display.width", 100)` і `display.max_columns = 20` виставлені заздалегідь.
- `input()` недоступний. Випадковість лише з фіксованим зерном (`np.random.default_rng(42)`),
  ніяких `datetime.now()`/`date.today()` у даних і розв'язках.
- Кожен запуск у свіжому просторі імен: змінні з попереднього запуску не живуть.

## Урок (`lessons/mN-назва.js`)

```js
export default {
  id: 'm7',
  title: 'Очищення даних',
  lessons: [
    {
      id: 'l7-1',                       // унікальний на весь контент
      title: 'Пропуски і типи',          // номер «7.1» застосунок додає сам
      theory: `<p>...</p>`,             // HTML: <p>, <code>, <strong>, <ul><li>
      examples: [
        { code: `...`, output: `...` },  // output: справжній вивід; images: true, якщо приклад малює
      ],
      exercises: [
        {
          task: 'Що зробити. Назви змінних і точний формат виводу.',
          starter: `...`,               // з чого починає учень; НЕ має проходити перевірку
          solution: `...`,              // повний робочий код
          expected: `...`,              // точний вивід (порівняння без пробілів у кінці рядків)
          check: `...`,                 // або/і перевірка на Python (див. нижче)
          hint: 'Підказка-напрямок, не готовий код', // звичайний текст; необов'язкова для вправ уроків
        },
      ],
    },
  ],
};
```

## Задача практикуму (`practice/pN-назва.js`)

Задача: кілька кроків над одними даними. Перед кроком k застосунок виконує `setup` і
**еталонні** розв'язки кроків 1..k-1 (їхній вивід прихований), тож у кроці k стан даних
завжди такий, як описано в умові, навіть якщо учень попередні кроки пропустив. Тому в
умові кожного кроку явно називай змінні, які існують на вході і які треба створити.

```js
export default {
  id: 'p4',
  level: 4,
  title: 'Повний цикл',
  description: 'Одне речення: які навички і що на вході.',
  tasks: [
    {
      id: 'p4-1',
      title: 'Продажі мережі кав'ярень',
      skills: ['to_datetime', 'groupby', 'matplotlib'],
      story: `<p>Хто ти, що за дані, яке питання бізнесу.</p>`,
      setup: `import io
import pandas as pd
RAW = """date,shop,amount
..."""`,                                 // код, що створює дані; учень бачить його як «Дані задачі»
      steps: [
        {
          title: 'Завантаж і оглянь',
          task: `<p>Прочитай <code>RAW</code> у DataFrame <code>df</code> і виведи <code>df.shape</code>.</p>`,
          starter: `# df = ...\n`,
          hint: 'pd.read_csv приймає файлоподібний об\'єкт: io.StringIO(RAW)',
          solution: `df = pd.read_csv(io.StringIO(RAW))\nprint(df.shape)`,
          expected: `(40, 3)`,
          check: `df = need("df", pd.DataFrame)\nexpect(len(df) == 40, "У df має бути 40 рядків")`,
        },
      ],
    },
  ],
};
```

Обов'язково для кожного кроку: `title`, `task`, `starter`, `solution`, `hint`, а також
`expected` та/або `check`. Кроків у задачі щонайменше 2.

`hint` у вправах і кроках звичайний текст без HTML: застосунок показує його як є, тож
`<code>` чи `&lt;` з'явилися б буквально. `npm test` ловить теги й сутності в підказках.

## Перевірка (`check`)

Python-код, що виконується після коду учня, якщо той відпрацював без помилки. Бачить
усі змінні учня (у копії простору імен) і має помічники:

| Помічник | Що робить |
|---|---|
| `need("df", pd.DataFrame)` | повертає змінну або падає з повідомленням «Не знайдено змінну…» / «має бути типу…» |
| `expect(умова, "повідомлення")` | якщо умова хибна, учень бачить повідомлення |
| `approx(a, b, tol=1e-6)` | порівняння чисел з відносним допуском |
| `OUTPUT` | усе, що код учня надрукував |
| `figures()` | список відкритих графіків matplotlib (Figure) |

Правила перевірок:

- Перевіряй суть, а не форму: значення, типи, кількість рядків, суми, порядок, а не те,
  що учень написав певне слово. Повідомлення конкретне і українською:
  «Колонка price має бути числовою, а зараз str», а не «Неправильно».
- Числа в перевірці або обчислюються в самій перевірці з сирих даних незалежним способом,
  або взяті з запуску еталону через verify. Не з голови.
- Не імпортуй у перевірці те, що змінює стан учня; імпорт `pandas as pd` чи `numpy as np`
  у перевірці безпечний.
- Перевірка графіка: кількість фігур і осей, тип (лінії `ax.get_lines()`, стовпці
  `ax.patches`, точки `ax.collections`), дані (`line.get_ydata()`, висоти `p.get_height()`),
  назва `ax.get_title()`, підписи осей `ax.get_xlabel()`/`ax.get_ylabel()`, легенда
  `ax.get_legend()`. Порівнюй дані з обчисленими значеннями через `approx`.
- `verify` вимагає, щоб стартовий код НЕ проходив: це захист від порожніх перевірок.

## Мова і стиль

- Українська, ясні короткі речення. Без канцеляриту і без «Чудово! Давай…».
- Довге (U+2014) і коротке (U+2013) тире заборонені всюди, і в коді, і в даних:
  дефіс для діапазонів (1-4), двокрапка або кома для пояснень. `verify` це ловить.
- Дані вигадані, але правдоподібні (гривні, українські міста, сезонність), без назв
  реальних компаній і людей.
- Брудні дані на рівнях 4-5 брудні по-справжньому і різнобічно: пробіли й регістр у
  категоріях, числа рядками з пробілами-розділювачами тисяч і комою як десятковою
  (`"1 299,50 грн"`), дати у двох-трьох форматах, дублікати, пропуски, очевидні викиди,
  одруківки в назвах. Кожен вид бруду має свій крок або явну частину кроку.

## Команди

```
npm run verify                    весь контент
npm run verify -- --only p4       один рівень (або урок l7-2, модуль m7, задача p4-1)
npm run verify -- --no-run        лише схема і тире, без Python
npm run verify -- --verbose       ще й справжній вивід кожного прикладу та еталону
npm run check                     модульні тести, verify і збірка разом
```

Звіт показує `ЗБІЙ <id>: …` і під ним справжній вивід. «Усе зелене» означає: кожен
еталон проходить, кожен стартовий код не проходить, схема і текст чисті.

Назви уроків і задач стоять у спільних колонках огляду й бічної панелі. Після нової чи
перейменованої задачі прожени ворота розкладки огляду (див. README):
`python scripts/check_layout.py --only home --widths 1440 --no-python`.
